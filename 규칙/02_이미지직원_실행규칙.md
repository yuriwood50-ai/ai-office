# 이미지 직원(Codex) 실행 규칙

적용 대상: 블로그이미지, 인스타카드 (두 직원 각각).

> 꿀벌블로그 `N번폴더 자동제작 운영 지침` 2-1절은 읽기만 하고 고치지 않아요. 2-1절은 "현재 환경의 서브에이전트 생성 도구로 이미지 담당을 실제 실행"하라고 하고, "실행이 불가능하면 이유와 대안을 알리고 이미지 단계는 미완료로 기록하며, 주 에이전트의 단독 제작을 별도 실행으로 표시하지 않는다"고 해요. 이 문서는 **스튜디오 환경에서 그 실행을 어떻게 하는지**를 추가로 정해요. 2-1절과 충돌하지 않아요.

## 실행 순서 (3단계)

1. **1단계 — 자동 실행:** 스튜디오 프로그램이 `codex exec`로 이미지 직원을 실행해요. 직원 카드(`직원/블로그이미지.md` 또는 `직원/인스타카드.md`)와 인계본 경로를 넘겨줘요.
2. **2단계 — 대표님 대기:** 1단계에서 이미지 생성이 안 되면(아래 '생성불가' 기준), 작가님이 **Codex 앱에 2-1절의 "이미지 담당에게 전달할 작업 지시문"을 붙여 직접 실행**해요. 화면에는 **'대표님 대기'** 로 표시해요.
3. **3단계 — 미완료:** 2단계도 안 되면 이미지 단계는 **미완료**로 기록해요. 결과물이 일부 있으면 지우지 않고 보존해요.

**어떤 경우에도 Claude는 이미지를 대신 만들지 않아요.** 개발자 Claude도, 글쓰기·마감 직원도 마찬가지예요. 미완료를 완료처럼 표시하거나, Claude가 만든 이미지를 Codex 결과처럼 쓰는 것도 금지예요.

## '생성불가' 판정 기준 (보완 A)

- `codex exec`가 **끝났는데**, 인계본에 적힌 **예정 파일 수만큼의 이미지가 출력 경로에 없으면** '생성불가'예요.
- **일부만 나와도 생성불가**예요. (예: 블로그 7장 예정인데 5장만 나옴)
- 직원별로 따로 판정해요. 블로그이미지는 PNG, 인스타카드는 JPG를 세요.
- 스튜디오 프로그램은 개수와 확장자만 세요. 이미지가 좋은지는 판정하지 않아요 (그건 마감의 독립 재검수예요).
- 예정 파일 수의 기준은 인계본 3번 항목(이미지별 예정 파일명)이에요.

## 이유를 화면에 남기기 (보완 B)

2단계로 넘어갈 때 스튜디오 화면에 아래를 남겨서, 작가님이 왜 직접 실행하는지 알 수 있게 해요.
- 어떤 직원인지 (블로그이미지 / 인스타카드)
- 예정 파일 수와 실제 나온 파일 수 (예: 예정 7장, 실제 5장)
- `codex exec`의 종료 코드와 오류 메시지 요약
- 실행 시각

## 프로그램 만들 때 확인할 것

스튜디오 프로그램을 만들 때 아래를 먼저 확인해요. 안 하면 잘못된 판정이 나요.

1. **`codex exec`의 쓰기 권한:** `codex exec`는 기본이 읽기 전용이라 **출력 폴더(`...\블로그_출력\`, `...\인스타_출력\`)에 쓸 수 있게 권한을 열어야 해요.** 열지 않으면 이미지는 만들었는데 저장을 못 해서 '생성불가'로 판정돼요. 이런 경우는 이미지 문제가 아니라 **권한 문제**예요. 열어야 하는 폴더는 출력 폴더만이고, 최종 납품 폴더와 지침 문서 폴더는 열지 않아요.
2. **`claude -p` 직원의 도구·폴더 허용:** `claude -p`로 실행하는 직원(주제기획, 글쓰기, 마감)은 **허락을 물어볼 수 없어요.** 물어볼 상황이면 그냥 멈추거나 실패해요. 그래서 직원마다 **쓸 수 있는 도구와 쓸 수 있는 폴더를 미리 정해서** 실행 때 넘겨야 해요. (예: 주제기획은 `작업\NN\`에만 쓰기, 글쓰기는 새 편 폴더와 보관 작업 폴더에만 쓰기, 마감은 최종 폴더에만 쓰기. 꿀벌블로그의 지침 문서와 기존 편 폴더는 읽기만.)
3. 허용 목록은 직원 카드의 **출력 파일 경로와 금지 사항**을 기준으로 만들어요. 카드와 허용 목록이 다르면 카드를 먼저 고쳐요.
4. 권한 문제로 실패했는지, 정말 이미지가 안 나온 건지 구분해서 화면에 남겨요 (종료 코드와 오류 메시지로 구분).

## 2단계(작가님이 직접 실행)에서 지킬 것
- 붙여 넣는 지시문은 2-1절 원문을 그대로 써요. 요약하지 않아요.
- 결과는 1단계와 같은 출력 경로에 저장해요. 이후 마감이 읽는 위치가 같아요.
- 작가님이 직접 실행해도 마감의 독립 재검수와 결재 ④는 그대로 거쳐요.
