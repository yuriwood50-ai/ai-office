# 상태와 파일

## 2026-10-24 최신 구현 — 기획자가 주제를 제안해요

- 기존 수동 ‘새 작업 만들기’를 **새 글 기획 시작**으로 교체했어요. 주제·편 번호 입력은 받지 않아요.
- Codex 기획자가 기존 문서·상태·편 폴더를 검토하고 다음 번호와 후보 3~5개를 제안해요. 승인 전에는 정식 `NN.json`을 만들지 않아요.
- 승인 전 실행·반려·오류·결과는 `작업/기획/실행ID/state.json`과 실행별 폴더에 보관해요.
- 작가님이 후보와 번호를 승인하면 `작업/NN/주제확정서.md`, `조사메모.md` 및 `상태/NN.json`의 **기획승인** 상태를 저장해요.
- 반려 이유를 남기고 다시 기획하면 기존 후보와 이유를 전달해요. 기획 승인 이후 글쓰기는 아직 자동 실행하지 않아요.
- 다음 편 번호는 기존 기록의 마지막 번호 다음으로 제안하고 99편은 제외해요. 승인 시 중복을 다시 검사해요.
- 아래 2026-10-23 ‘새 작업 등록’ 설명은 이전 구현 기록이에요. 현재 사용 흐름은 이 절을 따라요.

## 2026-10-23 구현 갱신 — 새 작업 등록

- 화면의 **새 작업 만들기**에서 편 번호·주제·요청사항을 입력하면 서버가 새 `상태/NN.json`을 만들어요.
- 신규 작업은 `기획준비` 단계로 저장해요. AI 직원 실행이나 주제 승인 완료를 뜻하지 않아요.
- 01~14편은 기존 콘텐츠용, 99편은 시험용으로 보호하고, 같은 편 번호는 덮어쓰지 않아요.
- 선택 항목 `요청사항`은 최대 2,000자이며 화면에서 다시 볼 수 있어요.
- 아래의 ‘화면은 읽기만 한다’는 설명은 **기존 상태 조회 기능**에 관한 설명이에요. 새 작업 등록 버튼은 예외이며, 기존 상태를 수정하는 버튼은 아직 없어요.

## 경로 약속
- 꿀벌블로그 루트: `{블로그}` (아래 `{블로그}`)
- 스튜디오 루트: `{스튜디오}` (아래 `{스튜디오}`). AI사무실은 **이 폴더 하나만** 써요. OneDrive 쪽 `문서\AI사무실`은 2026-10-23에 이 폴더로 합쳤어요.
- 편 번호 N은 숫자, NN은 두 자리(4편 → 04). 폴더 이름은 `NN_주제명` 형식이고 새 편은 짧은 영문 또는 한글 이름을 써요 (지침 10절).

## 폴더 구조

```
AI사무실\
  CLAUDE.md  개발자 Claude용 규칙
  규칙\     운영 규칙 문서 (01~04)
  직원\     직원 카드 5장
  사무실\   화면 프로그램 (실행.bat, server.js, office.config.json, public\, 그림\)
  상태\     NN.json (편마다 하나. 예: 15.json, 99.json) — 화면과 직원이 함께 보는 곳
  작업\NN\  직원 사이에 넘기는 스튜디오 쪽 기록 (프로그램·직원이 만들 때 생겨요)
  시험\     시험 실행 결과
```

- 화면 프로그램은 상태 폴더를 `사무실` 폴더 바로 위의 `상태`로 찾아요 (`office.config.json`의 `"상태폴더": "../상태"`). 그래서 직원 카드의 `{스튜디오}\상태\`와 화면이 보는 폴더가 같아요.

## 파일은 어디에 생기나

| 만드는 직원 | 파일 | 위치 |
|---|---|---|
| 주제기획 | 주제확정서.md, 조사메모.md | `{스튜디오}\작업\NN\` |
| 글쓰기 | 블로그N편_원고.md/.txt, 인스타N편_게시글.txt, 인스타N편_읽는대본.txt | `{블로그}\NN_주제명\` (새 폴더, 지침 10절 구조) |
| 글쓰기 | 이미지제작_인계.md | `{블로그}\99_보관\NN_제작검증_YYYYMMDD\` (새 하위 폴더, 지침 2-1절) |
| 블로그이미지 | 이미지 후보, 콘티, 비교 시트, 검수 보고서 | 위 보관 폴더 안 `블로그_출력\` |
| 인스타카드 | 카드 후보, 콘티, 비교 시트, 검수 보고서 | 위 보관 폴더 안 `인스타_출력\` |
| 마감 | 블로그N편_이미지/, 인스타N편_이미지/, 전체미리보기, 검수메모.md | `{블로그}\NN_주제명\` |
| 스튜디오 프로그램 | 편별 상태 | `{스튜디오}\상태\NN.json` |

- **새로 만드는 것만 쓰고, 기존은 안 고쳐요.** `{블로그}\NN_주제명\`과 `99_보관\NN_제작검증_*`은 이번 편을 위해 새로 만드는 폴더예요. 기존 편 폴더와 기존 보관 폴더 안의 파일, 지침 문서는 읽기만 해요.
- 보관 폴더를 만들면 `{블로그}\99_보관\README.md`에 위치와 용도를 한 줄 추가해야 하는데, README는 기존 파일이에요. **작가님이 허락할 때만** 추가하고, 허락이 없으면 스튜디오 쪽 `작업\NN\`에 기록 메모를 남겨요. (지침 2-1절은 README 기록을 요구해요.)

## 스튜디오 화면이 상태를 읽는 파일

편 번호에 따라 주 기준이 달라요.

| 편 | 주 기준 | 보조 |
|---|---|---|
| **15편부터** | `{스튜디오}\상태\NN.json` — 결재 상태, '대표님 대기' 같은 스튜디오만의 표시, 단계별 진행 | 아래 폴더 스캔과 세부 기록으로 교차 확인 |
| **01~14편** | `{블로그}\00_운영문서\smartbeetip_진행현황.md`의 상태표 (편, 주제, 실제 폴더, 상태 문장) — **기존 기록용으로만 읽어요** | 아래 폴더 스캔과 세부 기록 |

- **다음 편 번호와 이미 만든 주제**는 주제기획이 두 곳을 합쳐서 판단해요: 01~14편은 진행현황.md, 15편부터는 `{스튜디오}\상태\NN.json`. `상태\`가 비어 있으면 "15편 이후 기록 없음"으로 보고, 편 번호는 작가님 요청을 따라요 (`직원/주제기획.md`와 같은 표현).
- **진행현황.md에는 새 편을 추가하지 않아요.** 15편 이후 편을 거기에 적을지는 작가님이 나중에 정해요. 정하기 전까지 스튜디오는 그 파일을 읽기만 하고, 15편 이후의 상태를 거기서 찾지 않아요.
- **교차 확인 (모든 편):** 각 편 폴더의 필수 18파일 존재 여부. 원고 MD·TXT, 블로그 이미지 7장, 전체미리보기, 인스타 5장, 게시글, 대본, 검수메모. 편에 따라 예외가 있어요(14편은 블로그 6장·인스타 4장).
- **세부 기록 (모든 편):** 각 편 `검수메모.md`와 `99_보관\NN_제작검증_*\이미지제작_인계.md`.

주의: 진행현황 표는 사람이 쓴 문장이고 실제 폴더와 어긋날 수 있어요 (예: 13편 폴더명이 표에는 `13_DEVICE_COLOR_DIFFERENCE`, 실제는 `13_DEVICE_COLOR_DIFFERENCE_FINAL`). 알려진 불일치는 `규칙/04_운영문서_기준.md`에 모아뒀어요. 화면은 표와 폴더 스캔이 다르면 **다름 표시**를 해요. 둘 중 하나를 임의로 고르거나 표를 고치지 않아요.

## 상태 흐름
지침 16절의 흐름을 참고하되 스튜디오에 맞게 아래를 써요.

기획후보 → 기획승인(①) → 글쓰기중 → 인계승인대기 → 인계승인(②) → 이미지제작중 → 대표님대기 / 이미지미완료 → 마감검수중 → 완료확인대기(④) → 제작완료 → 디자인·게시승인대기(⑤)

위 흐름은 편 전체의 진행 단계예요. `NN.json`에서는 `"단계"` 칸에 적어요. 직원 한 명 한 명의 움직임은 아래 네 가지 `상태` 값으로 따로 적어요.

## 화면이 읽는 방식

사무실 화면은 `상태\NN.json` 파일을 4초마다 읽어서 캐릭터를 움직여요. 화면은 **읽기만** 하고, 파일은 직원(AI)이나 작가님이 써요.

- 파일 이름은 숫자 1~3자리 + `.json` 이에요. (`7.json`, `15.json`, `99.json`)
- `99.json`은 시험용이에요. 실제 편 번호와 겹치지 않게 남겨 둬요.
- 나중에 전자책팀·유튜브팀 방을 붙이면 `office.config.json`에서 방마다 다른 상태 폴더를 줄 수 있어요.

## NN.json 형식

```json
{
  "편": 99,
  "주제": "시험용 - 이 파일을 손으로 바꿔 보세요",
  "단계": "글쓰기",
  "직원": {
    "leader":  { "상태": "결재대기", "메시지": "서류 확인 중이에요" },
    "writer":  { "상태": "일함",     "메시지": "본문 쓰는 중" }
  },
  "마지막메시지": "인스타카드 5장 완성, 결재 부탁해요",
  "기록": [
    { "시각": "2026-10-23T10:00:00+09:00", "직원": "instacard", "내용": "카드 5장 완성" }
  ],
  "갱신시각": "2026-10-23T10:00:00+09:00"
}
```

| 칸 | 뜻 | 꼭 필요? |
|---|---|---|
| `편` | 편 번호 (숫자). 없으면 파일 이름의 숫자를 써요 | 권장 |
| `주제` | 이 편의 주제 | 권장 |
| `단계` | 지금 어느 단계인지 (예: 주제기획, 글쓰기, 이미지, 카드, 마감) | 권장 |
| `직원` | 직원별 상태. 키는 직원 `id` | 필수 |
| `직원.<id>.상태` | 아래 네 가지 중 하나 | 필수 |
| `직원.<id>.메시지` | 캐릭터에 마우스를 올리면 보이는 한마디 | 선택 |
| `마지막메시지` | 가장 최근 한 줄. `기록`이 비었을 때 대화창에 보여줘요 | 권장 |
| `기록` | 대화창에 쌓이는 메시지 목록. 최근 12줄만 보여줘요 | 선택 |
| `기록[].시각` | 시각 (ISO 형식 권장) | 선택 |
| `기록[].직원` | 직원 `id` (이름을 써도 돼요) | 선택 |
| `기록[].내용` | 한 줄 메시지 | 필수 |
| `갱신시각` | 파일을 마지막으로 고친 시각. 여러 편 중 "최신"을 고르는 기준이에요. 없으면 파일 수정 시각을 써요 | 권장 |

`직원` 안의 `"이름"` 같은 칸은 사람이 읽기 편하라고 적는 것이고, 화면은 무시해요.

## 상태 값 (이 네 가지만)

| 쓰는 말 | 화면에서 | 
|---|---|
| `일함` | 자기 책상에서 통통 튀어요 |
| `쉼` | 소파·커피 쪽으로 가요 (상태가 없거나 모르는 말이어도 쉼이에요) |
| `대표님대기` | 팻말을 들고 팀장석 쪽으로 와요. 작가님 확인이 필요할 때예요 |
| `결재대기` | 자기 자리에서 서류를 들고 있고, 팀장 책상 위에 📄 서류 아이콘이 생겨요 (여러 명이면 개수가 표시돼요) |

띄어쓰기는 무시해요. (`대표님 대기`도 돼요)

## 직원 id (블로그팀 기준)

직원 이름·담당 AI·색·자리는 `office.config.json`에 있어요. 상태 파일에서는 이름 대신 `id`를 써요.

| id | 이름 | 
|---|---|
| `leader` | 작가뀨 (팀장) |
| `topic` | 주제기획 |
| `writer` | 글쓰기 |
| `blogimg` | 블로그이미지 |
| `instacard` | 인스타카드 |
| `closer` | 마감 |

직원을 바꾸거나 늘리려면 `office.config.json`만 고치면 돼요. `id`를 바꾸면 `상태\*.json`의 키도 같이 바꿔야 해요.

## 쓰는 쪽이 지킬 약속

1. **JSON 문법을 지켜요.** 쉼표나 따옴표가 틀리면 화면은 그 파일을 읽지 못해요. 이때는 직전에 읽은 정상 내용을 그대로 보여주고, 화면 위쪽에 경고를 띄워요.
2. **통째로 한 번에 써요.** 파일 중간만 고치다 멈추면 깨진 파일로 읽힐 수 있어요.
3. **상태를 바꿀 때마다 `갱신시각`도 같이 바꿔요.**
4. **화면은 파일을 절대 고치지 않아요.** 화면에서 누른다고 상태가 바뀌지 않아요.

## 시험하는 법 (화면)

1. `사무실\실행.bat`을 더블클릭해서 화면을 열어요.
2. 메모장으로 `상태\99.json`을 열어요.
3. `"writer"`의 `"상태"`를 `"일함"` → `"쉼"`으로 바꾸고 저장해요.
4. 4초 안에 글쓰기 캐릭터가 책상에서 소파 쪽으로 걸어가면 성공이에요.
