## 3. 실행 방법 [확인]

1. `사무실\실행.bat` → `node server.js --open` → 브라우저에 `http://127.0.0.1:4173`
2. Node.js와, 직원이 쓰는 Codex CLI 또는 Claude Code CLI(로그인된 상태)가 필요해요.
3. 보안: 127.0.0.1에만 열림, Host·Origin·`X-Office-Request` 헤더 확인, CSP 헤더, 입력 크기 제한 — 잘 되어 있어요.

## 6. 분석 중에 생긴 일 (사고 기록)

서버를 새 코드로 확인하려고 임시 서버를 띄웠는데, **4173 포트에서 예전 서버가 이미 켜져 있었어요.** 제가 보낸 확인용 요청(`POST /api/planning/start`)이 그 예전 서버로 가서 **실제 기획 실행 1건이 시작**되었어요 (실행 ID `6f0f6886…`).

- 결과: Codex 사용 한도 때문에 시작 직후 실패했어요 [확인: events.jsonl에 "usage limit" 오류만 있음]. 그 서버는 예전 코드라 사용량 기록이 없으므로, **토큰·비용 사용량은 기록으로 확인할 수 없어요.** 이벤트에 한도 오류만 있다는 사실까지만 말할 수 있고, 몇 토큰을 썼는지는 추측하지 않아요 [확인 불가].
- 남은 흔적: `작업/기획/6f0f6886-…/` 폴더 1개 (상태 `failed`), 그리고 화면의 기획 기록 목록에 실패 건이 하나 더 보일 수 있어요. 지우지 않고 그대로 뒀어요.
- 교훈: 확인용 요청은 **포트를 먼저 확인**하고, 쓰기 요청(POST)은 날리지 않아요. 앞으로 시험은 별도 포트·임시 폴더로 해요.
- **지금도 예전 서버가 켜져 있어요.** 새 설정(블로그팀 비활성화 스위치)은 서버를 껐다 켜야 적용돼요. 끄고 `실행.bat`으로 다시 켜 주세요.
- **재발 방지 항목으로 등록했어요:** `NOTICE_CENTER_ARCHITECTURE.md` 12절 (R-1~R-6).

## 8. UI·디자인 시스템 [확인]

- 한 화면(`index.html`): 위쪽 제목·버튼·"저장된 편" 선택 → 알림 → 기획/글쓰기 패널 → **무대(사무실 그림)** → 대화창.
- **무대**: 배경 `01_empty_office.png`의 가로세로비에 맞춰 늘어나고, 캐릭터·소품은 모두 **무대 가로세로 %** 좌표(`office.config.json`)로 놓여요. 그래서 그림·자리를 설정만 바꿔 조정할 수 있어요.
- **방 탭**: `office.js`는 `설정.방`이 2개 이상이면 탭을 자동으로 보여줘요 → 새 "공고정보센터" 방을 **같은 화면 구조로 추가할 준비가 이미 되어 있어요.**
- 색 팔레트(`office.css` `:root`): 종이 `#fbf6ea`, 글자 `#3b2f1e`, 연한글자 `#85775f`, 벽 `#c9a66b`, 강조 `#f2a93b`. 패널은 `#fffdf7` 배경 + `#dcc39c` 테두리 + 둥근 모서리(14px).
- 캐릭터 직원별 색: 팀장 `#f2a93b`, 주제기획 `#6fb7e9`, 글쓰기 `#7bc67e`, 블로그이미지 `#e98fb8`, 인스타카드 `#b48ae0`, 마감 `#8a9aa8`.
- 화면의 글은 전부 `textContent`로 넣어 파일 내용이 코드로 실행되지 않아요(안전).

## 9. 캐릭터 이미지·애니메이션 자원 [확인]

- 이미지: `사무실/그림/` 15장 — 배경 1, 캐릭터 6, 소품 8 (서류, 팻말, 머그, 아이스커피, 노트북, 화분, 연필꽂이, 책).
- 애니메이션: 이미지 파일이 아니라 **CSS 애니메이션**이에요 (일함=통통 튀기, 상태 전환 시 자리 이동, 서류 개수 표시). 새 이미지가 없어도 상태 값만 바꾸면 움직여요.
- 캐릭터는 그림이 안 불러와지면 색 동그라미+이름 첫 글자로 대신 보여줘요(대체 표시).
- 그림 파일은 이번 작업에서 만지지 않았고 아카이브에서도 제외했어요(공통 자산).

## 10. 데이터 저장·작업 이력 구조 [확인]

| 위치 | 내용 | 비고 |
|---|---|---|
| `상태/NN.json` | 편별 단계, 직원별 상태·메시지, 최근 기록 100줄 | 화면이 읽는 유일한 상태. 사람이 읽기 쉬운 JSON. 쓰기는 통째로 |
| `작업/기획/<실행ID>/` | state.json, prompt.txt, schema.json, events.jsonl, stderr.log, result.json | 실행별 폴더, 재시도는 `실행-N` |
| `작업/글쓰기/<실행ID>/` | 위와 같은 구조 + `산출물/` | |
| `작업/NN/` | 주제확정서.md, 조사메모.md, 기획연결.json | 승인 후 생성 |
| `작업/사용량.jsonl` | 호출 기록(코드만 있고 파일 없음) | 3번 문제 |

**장점:** 파일 기반이라 눈으로 읽고 백업하기 쉬워요. 승인 기록·해시로 추적이 잘 돼요. **한계:** 목록 검색·중복 비교·통계에는 약해서(수천 건이면) 공고 센터에는 색인 파일이나 SQLite가 필요해질 수 있어요.
