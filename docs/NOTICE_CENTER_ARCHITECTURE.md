# 공고 정보센터 최소 개발 구조 제안 (NOTICE_CENTER_ARCHITECTURE)

- 작성일: 2026-10-24 / 최종 검수: 3차 / 상태: **설계안 — 코드는 아직 만들지 않았어요**
- **무엇이 확정이고 무엇이 제안인지는 10절 "결정 현황"이 기준이에요.** 다른 문서의 같은 내용과 다르면 이 문서의 10절을 따라요.
- 근거 문서: `PROJECT_AUDIT.md`(현재 코드), `NOTICE_CENTER_REQUIREMENTS.md`(무엇을 할지, 시험 시나리오), `TOKEN_OPTIMIZATION.md`(AI 호출·글자 수 규칙)
- 절 구성: 1 원칙 · 2 전체 그림(수집/검증 단계) · 3 캐릭터 역할 · 4 폴더 · 5 데이터 · 6 재사용 · 7 API · 8 MVP 범위 · 9 위험 · 10 결정 현황 · 11 환경 분리·Mock · 12 재발 방지 · 13 변경 파일 · 14 완료 기준 · 15 호출량
- 큰 방향: **새로 만들지 않고 지금 서버·화면·캐릭터 틀에 "방"을 하나 더 얹어요.** 의존성 추가 없음(Node 내장만), 파일 기반 저장.

---

## 1. 설계 원칙

1. **일반 코드가 일하고, AI는 해석만 해요.** 가져오기, 비교, 중복, 정렬, 날짜 계산, 상태 전이는 전부 일반 코드.
2. **한 번 한 일은 다시 하지 않아요.** 검증키(본문+규칙+조건+프롬프트 버전)가 같으면 AI를 다시 부르지 않아요(토큰 문서 3-5).
3. **실패는 기록하고 멈춰요.** 재시도 1회(일시 오류만), 한도 오류는 자동 재시도 없이 정지, 예산 초과 시 즉시 정지.
4. **제외와 삭제는 달라요.** 검색 대상·AI 검증·추천 노출·데이터 보존은 네 개의 독립 축이고, 기록은 지우지 않아요(요구사항 13절).
5. **외부로 나가는 길을 만들지 않아요.** 발송·제출 코드는 없어요.
6. **기존 것은 그대로 둬요.** 기존 코드는 가능한 한 수정하지 않고, 새 파일을 추가해요.

## 2. 전체 그림

```
[기관 목록 institutions.json] ──▶ ① 수집기(코드): 게시판 HTML/RSS 가져오기
                                      │ 목록 스냅샷 저장, 기관별 결과(성공/실패 종류) 기록
                                      ▼
                               ② 비교기(코드): 새 글/바뀐 글만 골라냄 (링크·해시 비교, 중복 판별)
                                      │ 대상이 0건이면 여기서 끝 → AI 호출 0회
                                      ▼
                               ③ 본문 수집(코드): 새/변경 공고의 공식 원문 페이지 텍스트 확보
                                      ▼
                               ④ 분류(코드): 인천 판별, 마감 확정 판정, 키워드 범위, 날짜 정규식,
                                      │      검증키 비교(변경 없음?) → '표지'만 붙임, 삭제 없음
                                      ▼
                               ⑤ AI 추출·판정 (배치, 한도 안에서): 구조화 JSON + 근거 문장   ← 유일한 모델 호출
                                      │      (AI 검증 '대상'으로 표지된 공고만)
                                      ▼
                               ⑥ 검증기(코드): 필수 필드·링크·날짜 형식·근거 문장이 원문에 실제로 있는지 대조
                                      ▼
                               ⑦ 저장·반영(코드): 공고 파일, 변경 이력, 실행 기록, 화면 상태, 사용량
```

⑤ 외의 모든 단계는 모델 없이 돌아요. 즉 **새 글이 없으면 AI를 한 번도 안 불러요.**

### 2-1. 두 개의 독립 단계 (확정)

| | **A. 수집 단계** (①~④) | **B. 검증 단계** (⑤~⑦) |
|---|---|---|
| 하는 일 | 게시판 가져오기, 새 글 판별, 중복·재공고 연결, 본문 확보, 분류(표지 붙이기) | AI 추출·적합도 판정, 원문 대조, 저장·반영 |
| AI | **절대 없음** (코드에 모델 호출 경로가 없음) | 여기만 (Mock이면 가짜 응답) |
| 실행 방법 | 버튼 "게시판 점검" | 버튼 "검증 실행" (수집 결과가 있을 때만) |
| 입력 | 기관 목록 | A가 저장한 공고 중 `AI 검증 = 대상`인 것만 |
| 출력 | `후보` 공고 + 기관별 점검 결과 + 스냅샷 | 공고 필드, 적합도, 검증 상태 |
| 비용 | 0 (네트워크만) | AI 호출 상한 적용 |
| 실패 영향 | 해당 기관만 `접속 실패/추출 실패` | 해당 공고만 `검증 필요`; A의 결과는 그대로 유지 |

- A와 B는 **서로의 내부 함수를 부르지 않고 파일(`공고\notices\`의 상태 값)로만** 이어져요. B가 한도 때문에 멈춰도 A의 수집 결과는 안전하고, B를 나중에 이어서 할 수 있어요.
- "수집 후 바로 검증" 편의 버튼을 만들더라도 내부적으로는 A 종료 → 호출 예상량 확인 → B 시작의 두 번 실행이에요(예상량 확인에서 작가님이 막을 수 있음).
- 분류(④)는 A에 둬요. 인천(확실)·마감 확정처럼 코드로 정해지는 건 AI에 보내지 않고(`AI 검증 = 생략(사유)`) `추천 노출 = 비노출`로 표지하되 **기록은 그대로 보존**해요. "검색 대상 제외", "AI 검증 제외", "추천 제외", "데이터 보존"은 서로 독립된 값이에요(요구사항 13절).

## 3. 직원(캐릭터) 역할 배치

캐릭터 6명의 수와 외형은 그대로 두고(확정), `office.config.json`의 **방 하나(`notice`)에 같은 그림을 다시 참조**해서 이름·역할만 바꿔요. 논리 역할 3개(검색·검증·운영)는 **코드 단계에 대응하는 화면 속 표시**일 뿐이에요. **역할마다 별도 AI 모델이나 에이전트를 실행하지 않아요.** 설정의 직원별 `AI` 칸은 `notice` 방에서 검증 담당(B 단계) 하나에만 의미가 있고, 나머지는 `코드`로 표기해요(배지에 "Claude/Codex"를 달지 않아요). `runner.js`가 읽는 직원 설정 모양과 충돌하지 않도록 구현 시 `AI: "코드"`를 허용값에 추가하거나 notice 전용 `AI모델` 칸 하나로 단순화해요(구현 단계에서 작가님께 보여드리고 결정).

| 기존 캐릭터 (그림 유지) | 기존 역할 | 새 역할 (제안) | 담당 단계 | AI 호출 |
|---|---|---|---|---|
| 작가뀨 | 팀장 | **팀장(변경 없음)** — 작가님 승인·결정 자리 | 승인/확인 요청 표시 | 없음 |
| 주제기획 | 주제 후보 | **검색 담당** | ①②③④ 수집·비교·본문 확보·분류 (A단계) | 없음 (일반 코드) |
| 글쓰기 | 원고 작성 | **검증 담당** | ⑤⑥ AI 추출·판정, 원문 대조 (B단계) | **여기만 AI (배치, 한도 안에서)** |
| 마감 | 최종 검수 | **운영 담당** | ⑦ 저장·마감 임박 정리·지원 상태·보고 (B단계 끝) | 없음 |
| 블로그이미지 | 이미지 | **대기(예비)** — 이번 MVP에서는 쉬는 모습 유지 | — | 없음 |
| 인스타카드 | 카드뉴스 | **대기(예비)** — 5단계 후보: 강의 제안서 보조 | — | 없음 |

- 두 이미지 담당 캐릭터는 지우거나 바꾸지 않고 "휴식" 상태로 둬요(캐릭터 수 유지, 확정). 이 둘에게 나중에 다른 역할을 줄지는 **미결정**이에요(10절).
- 기존 규칙 "이미지는 Codex 직원만 만든다"는 그대로예요. 공고 센터는 이미지를 만들지 않아요.
- 캐릭터 상태 움직임: 수집 중=검색 담당 `일함`, AI 판정 중=검증 담당 `일함`, 작가님 확인 필요(검증 필요·실패 기관)=`대표님대기`, 지원 상태 결정 대기=`결재대기`(팀장 책상에 서류 아이콘). **기존 4가지 상태·애니메이션 그대로 사용**해요.

## 4. 폴더·파일 구조 제안

```
AI사무실\
  사무실\                     (기존)
    server.js                 ← 소폭 수정: 공고 API 라우트 연결 (+비활성 스위치 이미 있음)
    office.config.json        ← 방 "notice" 추가 (같은 그림 재사용), 블로그 방은 그대로
    public\
      office.js office.css    ← 변경 최소: 방 탭은 이미 지원. 패널 렌더 호출만 추가
      notice-ui.js            ← 신규: 공고 패널(메인/상세/기관 관리)
    notice\                   ← 신규: 공고 센터 코드 (블로그 코드와 분리)
      store.js                공고·기관·실행 기록 읽기/쓰기(원자적 저장)
      collector.js            ① 게시판 가져오기 + 결과 분류
      differ.js               ② ④ 비교·중복·분류(표지 붙이기)
      extractor.js            ⑤ AI 호출(모델 클라이언트 주입) + 스키마 + 길이 제한
      verifier.js             ⑥ 검증
      metrics.js              지표 집계
      budget.js               호출 상한·글자 수 제한 (usage.js 위에)
      mock\                   시험용 가짜 자료의 원본(읽기 전용 씨앗, 명확히 시험용 표시)
    tests\notice.*.test.cjs   신규: 모의 시험
  공고\                       ← 신규: 데이터 (코드와 분리, 백업 대상)
    institutions.json         기관·게시판 목록
    settings.json             내 조건, 판정규칙, 마감 임박 기준, AI한도·글자수 제한, 모드(mock/real)
    settings.history.json     설정 변경 이력 (시각·이전 값·새 값)
    notices\<공고ID>.json     공고 1건 = 파일 1개 (변경 이력 포함). 제외·마감 공고도 여기에 그대로 (삭제·이동 없음)
    snapshots\<기관ID>\<날짜>.json   게시판 목록 스냅샷 (누락 추적용)
    runs\<실행ID>.json        실행 기록 (기관별 결과·지표·AI 호출)
    cache\<모드>\<검증키>.json   AI 결과 재사용 (mock/real 분리)
    misses.json               누락 기록
    mock\                     (mock 모드로 서버를 켰을 때의 실행 데이터. 위 파일들과 같은 구조. 11-1 참고)
  상태\공고\1.json            ← 캐릭터 움직임용 상태 (기존 상태 파일 형식 그대로)
  docs\ archive\              (이번에 생성)
```

- **가짜 자료는 두 곳에만 있어요:** 씨앗 `사무실\notice\mock\`(코드와 함께 있는 읽기 전용 원본)과, mock 모드 실행 데이터 `공고\mock\`(실제 `공고\notices\`와 폴더가 달라요). 모드가 `mock`일 땐 `공고\mock\`만 읽고 써서 실제 데이터를 오염시키지 않아요. 자동 시험은 이 둘이 아니라 **임시 폴더**를 써요(11-1).
- 공고 1건=파일 1개(JSON)로 시작 → 사람이 열어볼 수 있고 백업이 쉬워요. 공고가 약 2,000건을 넘거나 목록 화면이 느려지면 `node:sqlite`(Node 24 내장)로 옮기는 것을 그때 다시 제안해요(인터페이스를 `store.js`에 가둬 두기 때문에 교체 가능).

## 5. 데이터 모델 (요약)

**기관** `{ id, 이름, 유형, 지역, 우선순위, 게시판:[{id, 주소, 종류, 메모}], 사용, 점검주기, 마지막점검:{결과, 시각, 건수, 오류} }`

**공고** `{ id, 기관ID, 공고명, 분야, 대상, 지역, 접수시작, 접수마감{날짜, 시각|"미확인", 원문표기, 마감판정:'확정'|'불확실'|'해당없음', 판정근거}, 장소, 시간대, 금액, 자격{원문, 조건[]}, 제출서류, 접수방법, 공식링크, 첨부[], 최초발견{시각, 실행ID}, 마지막검증, 검증상태, 적합도{판정, 미충족[], 확인필요[], 근거[]}, 공고상태, 지원상태, 메모, 연결{재공고원본ID?}, 변경이력[{시각, 항목, 이전, 이후}], 출처필드, 원천('공식게시판'|'검색'|'가져오기'), **제외·보존**{ AI검증:{대상|생략, 사유}, 추천노출:{노출|비노출, 사유}, 보존:true(고정) }, **검증기록**{ 검증키, 검증시각, 결과출처:'AI'|'재사용', 모드:'mock'|'real', 본문잘림:true|false } }`

기관 쪽에는 `검색대상: 대상|제외(사유)`가 있어요(공고의 `AI검증`·`추천노출`·`보존`과 독립). 기관을 중지해도 그 기관의 기존 공고 기록은 그대로 남아요.

**점검결과(기관별, 실행 안에)** `{ 기관ID, 결과종류(6가지), HTTP상태, 가져온글수, 신규수, 소요ms, 오류문구 }`

**실행** `{ id, 시작, 종료, 모드, 대상기관수, 결과[], 지표{…}, AI{호출수, 입력토큰, 출력토큰, 추정/측정 구분}, 중단이유? }`

필드 이름은 한글 키를 써요(기존 `상태/NN.json`과 같은 방식). 정확한 형식은 구현 첫 단계에 `규칙/05_공고_자료형식.md`로 문서화하고 작가님 확인을 받아요(13-1, 14절).

## 6. 재사용 vs 신규

| 기존 코드 | 쓰임 | 수정 정도 |
|---|---|---|
| `server.js` 정적 파일·보안 헤더·Host/Origin 검사·입력 읽기 | 그대로 | 라우트 추가만 |
| `office.config.json` + `office.js` 방/직원/자리/소품/방 탭 | 새 방 `notice` 추가 | 설정만 + 작은 호출 추가 |
| 그림 15장, CSS 팔레트, `.planner-panel` 등 패널 스타일 | 그대로 | 신규 CSS는 기존 변수 사용 |
| `runner.js` (Claude/Codex 실행·읽기 권한) | ⑤ AI 호출 (실제 모드에서만, 지연 로딩) | ① `직원설정()`이 `방 blog`만 찾으므로 방 id를 받도록 ② 지금은 읽기 도구(Read/Glob/Grep)를 항상 켜므로 **"도구 없음" 옵션** 추가 (모델이 파일을 열지 않게) — 소 |

## 8. MVP(3단계) 구현 범위 — 지시서 12절과 1:1

| MVP 항목 | 구현 |
|---|---|
| 공고 등록 및 저장 | `store.js` + 수동 등록/가져오기 |
| 공식 링크 저장 | 공고 필수 필드 |
| 중복 판별 | `differ.js` (링크 정규화 + 근사 일치) |
| 검증 상태 관리 | 후보→원문확인됨→검증됨/검증실패 |
| 기관별 검색 성공·실패 기록 | `collector.js` 6종 결과 + `runs\` |
| 공고 목록 대시보드 | `notice-ui.js` 메인/목록/상세 |
| 작업별 AI 사용량 기록 | `usage.js` + `budget.js` |

MVP에서 **자동으로 안 하는 것:** 정기 자동 실행, 대규모 수집(처음엔 기관 5~10곳 수동 실행), 지원서 보조, 알림 발송.

**개발 순서 제안 (각 단계 끝에 작가님 확인)**
1. 자료 형식 문서 + `store.js` + Mock 자료 + 시험 (AI·네트워크 없음)
2. 기관 관리 + 수집기 + 결과 6종 분류(실제 게시판 1~2곳 읽기만, AI 없음)
3. 비교기·중복·변경 이력·누락 스냅샷
4. 공고 화면(새 방 탭) — 기존 디자인 그대로
5. ⑤ AI 추출(Mock → 실제 1회 시험) + 예산 장치
6. 4단계 실험(실제 공고 10건 비교)

## 11. 환경 분리와 Mock 구조 (구현 전 필수 설계)

### 11-1. 두 환경을 파일·포트·모드로 분리
| | 운영(실제) | 개발·시험 |
|---|---|---|
| 포트 | `office.config.json`의 4173 | **시험은 포트 0(OS가 빈 포트 배정)**; 고정 포트가 필요하면 4174 이상 별도 값 |
| 데이터 폴더 | `AI사무실\공고\` (mock 모드로 켜면 `공고\mock\`) | **자동 시험: 임시 폴더**(시험 실행마다 새로 만들고 끝나면 지움). `공고\`는 절대 쓰지 않음 |
| 상태 폴더 | `AI사무실\상태\공고\` | 임시 폴더 안 |
| 모드 | 기본 `mock`(제안, 10절), 작가님이 켜야 `real` | **항상 `mock` (코드로 강제, 확정)** |
| AI 클라이언트 | 모드에 따라 | **MockClient만** |

서버는 시작할 때 환경 변수로 위치를 받을 수 있게 해요: `OFFICE_DATA_DIR`, `OFFICE_PORT`, `OFFICE_MODE`. 시험 코드는 이 값을 반드시 지정하고, 지정하지 않으면 **시험이 시작을 거부**해요(실수로 운영 데이터를 쓰지 않도록).

### 11-2. 인스턴스 신원 확인 (사고 재발 방지의 핵심)
- 읽기 전용 `GET /api/notice/whoami` → `{ 인스턴스ID(서버 시작 때 만든 무작위 값), 시작시각, 모드, 데이터폴더, 포트, 코드버전 }`.
- **쓰기 요청(POST)을 보내는 모든 시험·스크립트·화면은 먼저 `whoami`로 "내가 띄운 그 서버"인지 확인**해요(인스턴스ID가 내가 방금 받은 값과 같을 때만 진행). 다르면 그 자리에서 중단.
- 서버를 새로 띄운 쪽은 시작 직후 "내 프로세스 PID가 그 포트를 잡았는가"를 확인하고, 포트가 이미 점유되어 시작에 실패하면 **시험을 실패로 끝내요**(기존 서버로 요청을 넘기지 않아요). 현재 서버는 포트 충돌 시 `process.exit(1)`로 끝나는데, 이전 사고는 그 뒤에 시험 스크립트가 이어서 요청을 보낸 것이 원인이었어요.
- 화면 상단에 항상 `모드 [MOCK]/[REAL]`와 `데이터: 운영/시험`을 표시해요.

### 11-3. Mock 모드에서 외부 AI 호출이 구조적으로 불가능하게 (4중 장치)
1. **주입 방식:** `extractor.js`는 `modelClient`를 인자로 받아요. Mock 모드에서는 `MockClient`가 들어가고, `RealClient`(= `runner.js`를 쓰는 쪽)는 **파일을 아예 불러오지 않아요**(필요한 순간에만 `require`). A단계(`collector.js`, `differ.js`)에는 모델 클라이언트가 **들어갈 자리 자체가 없어요**.
2. **명시적 3중 열쇠:** 실제 호출은 ⓐ `settings.mode === "real"` ⓑ 환경 변수 `OFFICE_ALLOW_REAL=1` ⓒ 실행 시작 시 화면에서 작가님이 "예상 N회 호출" 확인 버튼을 누름 — 셋이 모두 있어야 해요. 하나라도 빠지면 Mock.
3. **시험 안전망:** 시험 코드는 시작할 때 `child_process.spawn`/`exec`을 가로채서 호출되면 시험을 **즉시 실패**시켜요("Mock 시험에서 외부 프로세스 호출 시도"). 네트워크도 `fetch`를 가로채서 **허용 목록(시험용 가짜 서버 주소)** 밖이면 실패시켜요.
4. **기록:** 모든 호출은 `usage` 줄에 `모드: mock|real`을 남겨요. 시험 후 "real 호출 0건"을 자동 확인해요.

### 11-4. Mock 자료 규칙
가짜 자료(씨앗 `사무실\notice\mock\`, mock 실행 데이터 `공고\mock\`, 시험 코드 안의 자료)는 공고명에 `[시험용]`, 링크는 `https://*.invalid/…`, 기관명 앞에 `[시험]`. 실제 `공고\notices\`와 **폴더가 달라서** 섞일 수 없고, AI 결과 캐시도 모드별로 나뉘어 있어요(`cache\mock\`, `cache\real\`). 화면에서도 시험 데이터는 눈에 띄는 표지가 붙어요. 가짜 공고를 진짜처럼 보이게 만들지 않아요.
