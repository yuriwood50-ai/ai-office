# 공고 정보센터 기능 명세 (NOTICE_CENTER_REQUIREMENTS)

- 작성일: 2026-10-24 / 최종 검수: 3차 / 상태: **설계 기준 확정 + 세부 값·질문 일부 미확정** (이 문서는 구현이 아니라 약속서예요)
- 읽는 법: **확정** = 작가님이 지시·채택한 것 / **제안** = 제가 값이나 세부를 정해 본 것(미확정, 바꿀 수 있어요). 전체 확정·미확정 목록은 `NOTICE_CENTER_ARCHITECTURE.md` 10절이 기준이에요.
- 함께 보는 문서: 구조·폴더·API는 `NOTICE_CENTER_ARCHITECTURE.md`, AI 호출 수·글자 수 제한은 `TOKEN_OPTIMIZATION.md`. 같은 규칙이 여러 문서에 나오면 위 문서가 기준이고, 이 문서는 짧게 가리키기만 해요.

## 0. 목적과 원칙

- 목적: 프리랜서 일러스트레이터·AI 강사의 기회(강사 모집, 양성과정, 창작 지원/공모전)를 **놓치지 않고 찾고, 공식 원문으로 검증하고, 지원까지 관리**해요.
- 기본 원칙
  1. **공식 출처 없는 내용은 만들지 않아요.** 모르면 `미확인`.
  2. **검색 실패 ≠ 공고 없음.** 둘을 절대 같은 화면 표시로 쓰지 않아요.
  3. **밖으로 나가는 행동(지원서 제출, 기관 연락)은 작가님 승인 뒤에만.**
  4. **불확실한 날짜는 추정하지 않고 `확인 필요`로 처리해요.**
  5. **공고 기록은 삭제하지 않아요.** 제외·마감은 표지로만 구분해요(13절).
- 요구사항 번호(FR/NFR)는 구현·시험 항목과 연결하려고 붙였어요. 우선순위: **M**=MVP(3단계)에 필수, **S**=MVP 뒤(5단계 승인 후), **C**=나중에 검토.

### 0-1. 기존 공고 자동화 조건의 유지 (확정)

기존 ChatGPT 자동화의 **지역 범위, 대상 기관 유형, 적합/확인 필요/부적합 기준**은 바꾸지 않아요. 이 문서에 적힌 값은 작가님 지시서에 적힌 내용(지역 우선순위 1·2·3순위와 인천 제외, 기관 유형 11종, 판정 3종)이에요.

- **제가 확인하지 못한 것:** 기존 자동화가 쓰던 **세부 규칙**(예: 정확한 자격 판정 문구, 제외 키워드, 기관별 예외)은 이 환경에서 볼 수 없어요. 그래서 **짐작해서 채우지 않았어요.** 해당 칸은 `settings.json`의 `판정규칙`에 **비워 둔 채** 시작하고, 작가님이 기존 규칙을 알려주시면 그대로 옮겨요(질문 Q7).
- 규칙을 코드에 박지 않고 설정 파일에 두어, 기존 규칙이 바뀌어도 코드 수정 없이 따라가요.
- 새 조건을 임의로 추가하거나 기존 조건을 완화하지 않아요. 판정 규칙이 바뀌면 `판정 규칙 변경 이력`에 남겨요.

- FR-R2(M): "전국/온라인" 공고는 지역 `전국`으로 따로 두고 우선순위를 작가님이 정해요(현재 지시서에 없음 → 승인 필요 질문 Q1).

### 1-4. 기관 관리 (검색의 핵심 단위)
- FR-I1(M): 기관 1건 = 기관명, 유형, 지역, 우선순위, **공식 게시판 주소 1개 이상**, 게시판 종류(HTML 목록/RSS/외부 포털), 점검 주기, 사용 여부, 메모.
- FR-I2(M): 작가님이 화면에서 기관·게시판을 추가/수정/중지할 수 있어요.
- FR-I3(M): 기관별 마지막 점검 상태를 보관해요(5절).
- FR-I4(S): 검색엔진 탐색(키워드 × 지역)은 **게시판 점검의 보조**로만 써요. 검색엔진 결과에서 나온 공고는 반드시 공식 게시판/원문 링크를 확인해야 `검증됨`이 돼요.
- 하나의 검색어만 믿는 구조를 만들지 않아요(기관별 점검 + 키워드 탐색 병행).

### 2-2. 검증 상태 (FR-V1, M)
`후보` → `원문확인됨` → `검증됨` / `검증실패`.
- `후보`: 목록 페이지나 검색에서 발견만 한 상태
- `원문확인됨`: 공식 원문 페이지를 열어 본문을 확보한 상태
- `검증됨`: 필수 항목(기관명, 공고명, 공식 링크, 마감일 또는 "상시/미확인" 명시, 모집 대상)이 원문과 일치해서 확인된 상태
- `검증실패`: 원문이 열리지 않거나 내용이 모순인 상태(이유 저장)

## 3. 적합도 판정

### 3-1. 판정 3종 (기존 기준 유지)
**적합 / 확인 필요 / 부적합** + **근거(문장 단위)**.

### 3-2. 판정 규칙 (FR-F1, M) — 코드가 먼저, AI는 애매할 때만
| 구분 | 내용 | 처리 |
|---|---|---|
| 명시적 미충족 | 인천 지역(13-2의 확실한 경우), **확정된** 마감 지남(13-3), 자격이 명시적으로 불가(예: 법인만, 특정 자격증 필수, 거주지 제한 불일치) | `부적합` + 근거 원문 (인천·마감은 코드 판정, 사유 코드 저장) |
| 추가 확인 필요 | 자격이 모호, **마감일이 불확실하거나 마감 시각 없음**, 인천 여부가 불확실, 첨부파일 안에만 조건이 있음, 원문 열람 불가 | `확인 필요` + **무엇을 확인해야 하는지** 목록 |
| 충족 | 분야 A/B/C에 해당 + 지역 우선순위 안 + 명시적 제한 없음 | `적합` |

적합도 3종은 기존 기준 그대로예요. `부적합`이라고 해서 기록을 지우지 않아요(13절).

- FR-F2(M): "명시적 지원 자격 미충족"과 "추가 확인 필요 조건"은 **화면에서 다른 칸**으로 보여줘요(섞지 않아요).
- FR-F3(M): 작가님의 개인 조건(사업자 여부, 거주지, 보유 자격 등)은 `내 조건` 설정에 저장해서 판정에 써요. 현재 정보가 없으므로 **초기값은 비어 있고 작가님이 입력해야 해요**(Q2). 비어 있는 조건이 필요한 공고는 `확인 필요`가 돼요.
- FR-F4(M): 작가님이 판정을 수동으로 바꿀 수 있고, 바꾼 사람·시각·이유를 기록해요.

## 4. 변경·중복 관리

### 4-1. 공고 상태 (FR-S1, M)
`신규`, `기존`, `수정`, `마감 연장`, `재공고`, `접수 마감`, `검증 실패` — 이전 점검 결과와 비교해서 자동 부여해요.

### 4-2. 중복 판별 (FR-D1, M) — 전부 일반 코드
1. 정확 일치: 공식 링크(주소 정규화 후) 같으면 같은 공고.
2. 근사 일치: 같은 기관 + 공고명 정규화(공백·괄호·"[모집]" 등 제거) 유사도가 기준 이상 + 접수 기간이 겹치면 **후보 중복**으로 묶고 작가님 확인(자동 병합은 하지 않아요).
3. 서로 다른 기관이 같은 사업을 재게시한 경우는 "같은 사업, 다른 게시처"로 연결만 하고 합치지 않아요.

### 4-3. 변경 이력 (FR-D2, M)
- 이전 점검과 달라진 항목(특히 **마감일, 접수 기간, 자격, 모집 인원, 첨부파일**)은 `변경 이력`에 **이전 값 → 새 값, 발견 시각**으로 쌓아요.
- `재공고`·`마감 연장`은 새 공고를 만들지 않고 기존 공고에 **연결**하되, 변경 사실을 별도 줄로 강조해요.
- 이력은 지우지 않아요.

## 5. 점검(검색) 성공·실패 관리

### 5-1. 기관별 점검 결과 (FR-C1, M)
| 값 | 뜻 |
|---|---|
| 정상 완료·신규 없음 | 게시판 목록을 정상으로 읽었고 새 글이 없음 |
| 정상 완료·신규 발견 | 정상으로 읽었고 새 공고 후보 있음 |
| 접속 실패 | 네트워크 오류·시간 초과·HTTP 오류(상태 코드 저장) |
| 자료 추출 실패 | 접속은 됐는데 목록을 해석하지 못함(구조 변경, 자바스크립트 렌더링, 차단 페이지 등) |
| 검증 필요 | 읽긴 했지만 결과가 이상함(예: 평소 10건인데 0건, 페이지가 비정상적으로 짧음) |
| 검색 미실행 | 이번 실행에서 건너뜀/중지/예산 소진 |

- **FR-C2(M):** `신규 없음`은 **정상 완료일 때만** 표시해요. 그 외는 절대 "없음"으로 표시하지 않아요.
- **FR-C3(M):** "평소보다 급격히 적음" 판단은 일반 코드(최근 N회 평균 대비)로 `검증 필요`를 붙여요.
- **FR-C4(M):** 실패/검증 필요/미실행 기관은 화면의 **"다시 확인할 기관"** 목록에 따로 모아서 한 번에 재점검할 수 있어요.

### 5-2. 점검 기록 (FR-C5, M)
실행 1회 = 실행 ID, 시작/종료 시각, 대상 기관 수, 기관별 결과·소요 시간·HTTP 상태·가져온 글 수, 신규/변경 건수, AI 호출 수·토큰.

## 6. 누락 추적

- FR-M1(M): "최근 30일 재확인" 기능 — 선택한 기간의 모든 활성 기관 게시판을 **다시 훑어** 지금 있는 공고와 저장된 공고를 비교해요(게시판에 아직 남아 있는 글에 한해서요).
- FR-M2(M): 사후 발견(과거에 올라왔는데 뒤늦게 찾은 공고)을 `누락 기록`으로 남겨요:
  - 해당 공고 / 원래 게시일(원문에 있으면) / 최초 발견일 / **누락된 검색 실행(그 기간의 실행 목록 + 해당 기관 결과)** / 추정 누락 원인 / 재발 방지 조치
- FR-M3(M): **추정 원인은 근거가 있을 때만 적어요.** 허용되는 원인 값: `해당 기관 점검 실패`, `해당 기관 점검 안 함`, `그 시점에 게시판에 없었음(게시일이 더 늦음)`, `목록 추출은 됐으나 공고로 인식 못 함`, `키워드 범위 밖`, **`원인 확인 불가`**. 기록이 부족하면 반드시 `원인 확인 불가`예요(꾸며 쓰지 않아요).
- FR-M4(S): 누락이 반복되는 기관을 표시하고 점검 주기를 올릴지 제안.

## 12. 수집과 검증의 분리 (확정, FR-P1, M)
- **A. 수집 단계**: 기관 게시판 점검 → `후보` 공고와 기관별 결과를 저장. **AI를 부르지 않아요.**
- **B. 검증 단계**: 저장된 `후보` 중 **AI 검증 대상**만 입력으로 받아 AI 추출·적합도 판정 → 코드 검증 → 저장. 한도(실행당 5, 하루 15, 재시도 1; 사용자 변경 가능, 기준: 토큰 문서 3-4) 적용.

- 인천·확정 마감처럼 코드로 정해지는 분류는 A에서 표지만 붙여요. AI에 보낼지는 13절의 `AI 검증` 축이 정해요.

## 13. 제외·보존·추천 기준 (확정 방침, 세부 값은 제안)

### 13-1. 네 개의 독립 축 (FR-E1, M)
한 공고에 아래 네 값이 **각각 따로** 저장돼요. 한 축의 값이 다른 축의 값을 바꾸지 않아요(예: "AI 검증 생략"이 "삭제"를 뜻하지 않아요).

| 축 | 묻는 것 | 값 | 정하는 곳 |
|---|---|---|---|
| ① 검색 대상 | 이 기관·게시판을 점검하나? | `대상` / `제외(사유)` | 기관 설정 (인천 기관 등록 불가, 작가님이 중지) |
| ② AI 검증 | 이 공고를 AI에 보내나? | `대상` / `생략(사유)` — 사유: `코드판정-지역`, `코드판정-마감확정`, `변경없음(재사용)`, `한도`, `미처리`, `작가님보류` | 코드 |
| ③ 추천 노출 | 사용자에게 추천하나? | `노출` / `비노출(사유)` | 코드 (작가님이 수동으로 바꿀 수 있고 이유가 기록돼요) |
| ④ 데이터 보존 | 기록을 남기나? | **항상 보존** — 삭제 기능이 없어요 | 고정 |

### 13-2. 인천 공고 (FR-E2, M)
- ① 인천 기관·게시판은 검색 대상으로 **등록할 수 없어요**.
- 다른 경로(전국 단위 게시판, 검색엔진, 가져오기)로 인천 공고가 **발견된 경우**: ② `생략(코드판정-지역)` ③ `비노출(인천)` ④ **보존**(기관, 공고명, 공식 링크, 게시일·마감 원문 표기, 최초 발견일, 사유). 적합도는 `부적합`, 사유 `지역 제외(인천)`.
- **인천이 확실할 때만** 비노출해요: 기관 소재지가 인천이거나, 원문에 인천 한정이 명시된 경우. 불확실하면 추정하지 않고 `확인 필요`(사유: 지역 불확실)로 노출해요.
- 인천 소재 기관이 낸 전국·온라인 대상 공고의 처리는 질문 Q8 (초기값: 비노출).

### 13-3. 마감 공고 (FR-E3, M)
- **마감 확정** = 접수 마감 날짜가 원문에서 **확실히** 읽히고, 그 날짜가 지난 경우. 시각이 없으면 그날이 **끝난 다음 날부터** 마감이에요(당일은 `마감 임박(시각 미확인)`).
- 마감 확정 공고: ① 게시판에서 계속 읽혀요(검색 대상에서 빼지 않아요) ② `생략(코드판정-마감확정)` ③ `비노출(마감)` ④ **보존**. 공고 상태 `접수 마감`, "제외·마감 보관" 보기로 가요. **파일을 지우거나 옮기지 않고 표지만 바뀌어요.**
- **불확실한 마감일**(`미확인`, 해석 불가, "11월 말", 요일 불일치, 연도 없음 등): 마감으로 **추정하지 않아요**. 적합도 `확인 필요`, 사유 `마감일 불확실`, 추천 목록에는 "확인이 필요한 공고"에만 노출해요. AI 검증 대상이에요(한도 안에서). AI가 준 마감일은 원문 대조를 통과해야만 확정으로 쳐요.
- 마감 후에 발견된 공고도 **버리지 않고** `접수 마감`으로 등록하고 6절 누락 기록을 만들어요. 이것이 누락 분석의 핵심 자료예요.
- 마감 공고의 AI 필드 추출이 필요하면 작가님이 수동으로 요청해요(한도 적용).

### 13-4. 변경 없는 공고의 AI 재검증 생략 (FR-E4, M)
같은 공고의 정규화 본문·판정 규칙·`내 조건`·프롬프트 형식이 이전 검증 때와 같으면 AI를 다시 부르지 않고 이전 결과를 재사용해요(`생략(변경없음)`). 세부 키 구성과 무효화 조건: 토큰 문서 3-5. 마감 임박·마감 확정 같은 **날짜 기반 상태는 코드가 매번 다시 계산**하므로 AI가 필요 없어요.

### 13-5. 보존 최소 기록 (FR-E5, M)
모든 공고(제외·마감·부적합 포함)는 최소한 다음을 남겨요: 기관, 공고명, 공식 링크, 게시일(원문 표기), 마감(원문 표기+해석 결과), 최초 발견일·발견한 실행, 상태·분류·사유, 변경 이력. 게시판 목록 스냅샷(6절)도 기관별로 계속 쌓아요. 이 기록이 6절 누락 분석에 쓰이므로 자동 삭제하지 않아요.

## 14. 시험 시나리오 (Mock/임시 환경에서만 실행, 외부 AI·실제 사이트 호출 없음)

모든 자료는 `[시험용]` 표지, 링크는 `.invalid` 주소. 각 시나리오는 "입력(가짜 게시판 응답) → 기대 결과"로 자동 시험해요. 결과가 기대와 다르면 시험 실패예요.

| ID | 시나리오 | 입력 | 기대 결과 |
|---|---|---|---|
| **S1** | **과거 누락 공고의 사후 발견** | 1회차 점검에서 기관 X가 접속 실패(게시판에 공고 P 있었음). 3일 뒤 2회차에 P가 보임(원문 게시일 = 1회차 이전) | P는 `신규`로 등록 + 누락 기록 생성: 원래 게시일, 최초 발견일, 누락된 실행 = 1회차, 추정 원인 = `해당 기관 점검 실패`(1회차 기록으로 **근거 있음**). 근거 없는 변형(S1b): 1회차 기록이 아예 없으면 원인 = **`원인 확인 불가`** |
| **S1c** | 30일 재확인 | 최근 30일 스냅샷과 현재 게시판 비교, 스냅샷에 없는 글 2건 | 2건이 `누락 후보`로 나오고 사후 발견 누락 수 +2, 이미 내려간 글은 "복구 불가" 명시 |
| **S2** | **재공고** | 같은 기관·같은 사업명, 새 링크, 접수 기간이 새로 시작 | 새 공고를 만들되 원본과 **연결**, 상태 `재공고`, 변경 이력에 "재공고: 이전 마감 → 새 접수 기간" |
| **S2b** | **마감 연장** | 같은 링크, 마감일만 뒤로 | 새 공고 안 만듦, 상태 `마감 연장`, 변경 이력 `마감: 이전 → 이후` + 강조 |
| **S2c** | 근사 중복 | 같은 기관 제목만 괄호/공백 차이, 같은 기간 | 자동 병합하지 않고 **후보 중복**으로 묶어 작가님 확인 대기 |
| **S3** | **마감일 오류 1: 날짜 형식** | 원문 "접수: 10.31(금) 18시", 연도 없음 / "~11월 말" / 상시 모집 | 연도는 게시 시점으로 추론하지 않고 규칙에 따라 해석하되 **원문 표기 병행 저장**, "11월 말"은 날짜 확정 불가 → 마감 `미확인`+`확인 필요`, 상시는 `상시` |
| **S3b** | **마감일 오류 2: 원문과 AI 값 불일치** | Mock AI가 원문에 없는 마감일을 반환 | 검증기가 원문 대조 실패 → 마감 `AI추정`으로 강등, `검증됨` 불가 |
| **S3c** | **마감일 오류 3: 요일 불일치/이미 지난 날짜** | "10.31(월)"처럼 요일이 달력과 안 맞음 / 마감이 오늘 이전 | 요일 불일치는 `확인 필요`(원문 오탈자 가능, **마감 추정 안 함**). 날짜가 확실히 읽히고 이미 지났으면 `접수 마감`(13-3): AI 검증 생략, 추천 비노출, **기록 보존** |
| **S3d** | 시각 없는 마감 | "10월 31일까지" | 시각 `시각 미확인`(23:59 등 임의 값 금지) |
| **S4** | **공식 게시판 접속 실패 (종류별)** | 시간 초과 / HTTP 500 / HTTP 403 / DNS 실패 | 모두 `접속 실패`(상태 코드·오류 저장), **`신규 없음`으로 표시되지 않음**, "다시 확인할 기관" 목록에 등장 |
| **S4b** | 추출 실패 | 접속 200이지만 목록 구조를 해석 못 함(빈 HTML/로그인 페이지) | `자료 추출 실패` |
| **S4c** | 급격히 적은 결과 | 평소 10건 → 이번 0건(정상 응답) | `검증 필요`(정상 완료·신규 없음으로 확정하지 않음) |
| **S4d** | 재점검 | S4의 실패 기관만 다시 실행 | 실패 기관만 재시도, 이미 성공한 기관 재호출 없음, 결과 갱신 |
| **S5** | **지역 규칙** | 인천 공고 / 용인 / 서울 / 경기 기타 | 인천(확실): AI 검증 생략·추천 비노출·**기록 보존**·사유 `지역 제외(인천)`. 인천 기관 등록은 거부. 인천 여부 불확실 시 `확인 필요`. 용인 우선순위 1, 서울 3, 경기 기타 2 |
| **S6** | **적합도 3종 + 미충족/확인 구분** | 명시적 자격 불가 / 자격 모호 / 충족 | 각각 `부적합`(미충족 칸) / `확인 필요`(확인 항목 칸) / `적합`. 두 칸이 섞이지 않음 |
| **S7** | **한도** | 신규 공고 40건을 한 번에 검증 요청 | 배치 5건 × 5회에서 정지, 나머지 15건 `미처리`, 6번째 호출 없음. 하루 합계 15회 초과 시 거부. 재시도는 호출당 1회, 한도 오류는 **자동 재시도 없이** 전체 중지(남은 공고 `미처리`) |
| **S7b** | 설정 변경 | 실행당 상한을 5→3 | 다음 실행부터 3 적용, 변경 이력 기록. 값 `-1`/`abc` → 기본값 5로 복귀+경고 |
| **S8** | **Mock 안전/환경 분리** | 전체 시험 실행 | real 호출 0, `spawn`/외부 네트워크 0, 운영 `공고\`·`상태\` 해시 불변 |
| **S9** | **서버 신원 확인(R-1)** | 시험 포트에 다른 서버가 이미 떠 있음 | 시험이 시작을 거부하고 쓰기 요청을 한 건도 보내지 않음 |
| **S10** | 가져오기 | 기존 자동화 결과 CSV(링크 포함) | `후보`로 등록, 출처 `가져오기`, 중복 링크는 합치기, `검증됨` 아님 |
| **S11** | 외부 행동 금지 | UI/서버 전체 탐색 | 지원서 제출/발송/기관 연락 라우트·버튼이 존재하지 않음 |
| **S12** | **마감 공고 보존** | 마감 확정 공고가 게시판에 계속 남아 있음 / 이미 내려간 뒤 스냅샷에만 있음 | 삭제·이동 없음. `접수 마감`+추천 비노출+보관 보기. 스냅샷·변경 이력·누락 기록에서 계속 조회됨. 파일 수 전후 동일 |
| **S12b** | 마감 후 발견 | 마감 지난 뒤 처음 발견 | `신규`+`접수 마감`으로 **등록**되고 누락 기록 생성(삭제·무시 아님), AI 호출 0 |
| **S13** | 인천 사후 발견 | 전국 게시판에서 인천 한정 공고 / 인천 소재 기관 공고 | 추천 목록·지표 "신규 추천"에 안 나옴, 보관 보기에 사유와 함께 있음, 기록 보존, AI 호출 0, 코드 제외 건수 +1 |
| **S14** | **축 독립성** | 인천이면서 마감 확정인 공고 / 검색 대상 중지한 기관의 기존 공고 | 네 축이 각각 올바른 값(사유 둘 다 기록), 기관을 중지해도 **기존 공고 기록은 그대로 보존** |
| **S15** | **변경 없으면 AI 재검증 생략** | 같은 공고를 두 번 점검(본문 동일) / 본문 한 글자 수정 / `내 조건` 변경 | 첫 번째 재점검: AI 호출 0, `생략(변경없음)`. 본문 수정: 재검증 대상. 내 조건 변경: 해당 판정만 무효화(토큰 문서 3-5) |
| **S16** | **길이 제한** | 본문 6,000자 초과 공고 / AI 응답이 출력 상한 초과 | 입력은 자르고 (자른 사실 기록) 필수 항목을 못 찾으면 `확인 필요`; 초과 응답은 거부하고 `검증 필요`(재시도로 같은 요청을 반복하지 않음) |

## 15. 이번 범위 밖 (명시)
자동 정기 검색, 마감 알림, 지원서 작성 보조, 강의 제안서 연결, 영업·지원 이력 관리는 **MVP 결과를 보고 작가님이 승인한 뒤** 결정해요. 대규모 자동 수집도 MVP에서는 하지 않아요.

## 16. 작가님께 확인받을 질문 (구현 전)
- **Q1.** "전국/온라인" 공고의 지역 우선순위는? (포함 여부 포함)
- **Q2.** 지원 자격 판정에 쓸 작가님 조건: 사업자등록 여부, 거주지, 활동 형태(개인/단체), 보유 자격증, 경력 연수, 원하는 최소 강의료 등
- **Q3.** 처음 등록할 기관 목록과 게시판 주소(용인·성남·수원 위주로 20~30곳을 제안하면 작가님이 고르는 방식이 좋아요). 기관 주소는 제가 지어내지 않고 **작가님이 알려주신 것 + 공식 사이트에서 확인한 것**만 넣어요.
- **Q4.** 마감 임박 기준(며칠?), 점검 주기(하루 1회? 수동만?)
- **Q5.** 기존 ChatGPT 자동화 결과를 가져올 방법(복사해 붙여넣기 가능한 형식이 있는지)
- **Q6.** 공고 센터 검증 단계에서 쓸 AI(Claude/Codex)와 구독/API 구분. (호출 상한 5/15/1은 채택 완료, 변경은 화면에서 가능)
- **Q7.** 기존 ChatGPT 공고 자동화의 **세부 판정 규칙**(제외 키워드, 자격 판정 문구, 기관별 예외, 우선순위 가중)을 문서·캡처·붙여넣기로 알려주세요. 알려주시기 전까지는 `판정규칙`을 비워 두고 지시서에 있는 조건만 적용해요.
- **Q8.** 인천 소재 기관이 낸 **전국·온라인 대상** 공고는 어떻게 할까요? (초기값: 비노출. 13-2)
