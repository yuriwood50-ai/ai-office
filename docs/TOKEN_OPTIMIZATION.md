### 3-2. 호출 구조
- **B단계 한 번의 AI 호출 수 = (AI 검증 대상 공고 수 ÷ 배치 크기) 올림.** 배치 크기 초기값은 **5건**(제안, 변경 가능). 이 문서·요구사항·시험 시나리오의 모든 예시는 5건 기준이에요.
- 공고 20건이 AI 검증 대상: 4회. 대상 0건인 날(신규 없음, 전부 변경 없음/코드 제외): **0회**.
- **공통 문맥 최소화:** 호출마다 보내는 고정 문맥은 *역할 한 문장 + 출력 필드 정의 + 판정 기준 요약*으로 **약 1,500자 이내**(제안). 지침 문서·직원 카드·`내 조건` 전문을 붙이지 않고, 판정에 필요한 항목만 발췌해요. 같은 호출 안에서 공고 5건이 이 문맥을 **한 번만** 공유해요.
- **모델이 파일이나 웹을 직접 읽지 않아요.** 필요한 본문은 코드가 잘라서 프롬프트에 넣고, 도구는 모두 끈 상태로 실행해요(현재 `runner.js`는 읽기 도구를 항상 켜므로 "도구 없음" 옵션이 필요해요 → 아키텍처 13-2). 모델이 문서를 열어 보며 입력이 불어나는 일을 막기 위해서예요.
- **출력 제한:** JSON 스키마로 필드를 고정하고 문자열 `maxLength`, 배열 `maxItems`를 둬요(근거 문장은 필드당 약 120자 이내, 확인 항목은 최대 5개 등). 서술형 설명 필드는 만들지 않아요. CLI가 출력 토큰 상한을 직접 지원하는지는 **미확인**이라, 스키마 제한 + 지시문 + **코드 검사**(상한 초과 응답은 거부)로 막아요. 거부된 응답은 재시도하지 않고 `검증 필요`로 둬요.
- 모델 선택: 추출은 가벼운 모델로도 충분한지 4단계 실험에서 비교(모델·추론강도는 직원 설정 칸에 있음). **추론강도는 낮게 시작**해요.

### 3-3. 호출 전 사전 점검 (비용 안전장치)
1. 모드 확인: `mock`이면 실제 호출 경로가 **존재하지 않아요**(장치: 아키텍처 11-3). 이 문서는 그 규칙을 다시 적지 않아요.
2. 이번 실행의 **예상 호출 수·예상 입력 글자 수**를 계산해서 화면에 보여주고, 상한 초과면 시작하지 않아요(작가님 확인). 이 값은 **추정**이라고 표시해요.
3. 실행 중 누적이 상한을 넘으면 즉시 중지. 한도 오류가 나면 **자동 재시도 없이** 중지(2절 #8).

### 3-4. 한도·예산 (2026-10-24 작가님이 초기 안전 기준으로 채택 — 언제든 변경 가능)
| 설정 (`공고\settings.json`의 `AI한도`) | 초기값 | 비고 |
|---|---|---|
| 실행당 AI 호출 상한 | **5회** | **재시도 호출도 포함해서 센다.** 초과분 공고는 `미처리` 목록으로 |
| 하루 AI 호출 상한 | **15회** | 날짜가 바뀌면(한국 시간 0시) 0으로. 재시도 포함 |
| 재시도 | **호출당 1회** | 일시 오류만. 스키마 오류·한도 오류는 재시도 안 함 |
| *(아래는 모두 초기 제안값 — 미확정, 설정에서 변경 가능)* | | |
| 공고 1건 본문 입력 상한 | 6,000자 | 초과분은 자르고 "잘림" 기록. 필수 항목을 못 찾으면 `확인 필요` (요약해서 넣지 않음) |
| 호출당 입력 합계 상한 | 20,000자 | 공통 문맥(약 1,500자) 포함. 넘으면 그 호출의 공고 수를 줄여요 |
| 호출당 출력 상한 | 약 6,000자 (공고당 약 1,200자) | 스키마 제한 + 코드 검사. 초과 응답은 거부 |
| 배치 크기 | 5건 | 위 입력 상한이 먼저 닿으면 더 적게 |
| 연속 실패 | 2회면 전체 중지 | |
| 금액 한도(API 방식일 때만) | 작가님 지정 | 구독형은 금액 개념이 없음 → 호출 수 기준 |

글자 수는 토큰이 **아니에요**. 한국어는 글자당 토큰 수가 일정하지 않아서, 글자 수 상한은 "대략적인 안전 장치"일 뿐이고 **실제 토큰은 호출 뒤 CLI가 알려주는 값(측정)** 으로만 기록해요.

**변경 방법 설계:** 위 값은 코드에 박지 않고 `settings.json`에 둬요. 공고 화면의 "설정" 칸에서 작가님이 바꾸면 **다음 실행부터** 적용되고, 바꾼 시각·이전 값·새 값이 `settings.history`에 남아요. 상한을 올리는 변경은 확인 한 번을 더 물어요(실수로 0 하나 더 붙이는 것 방지). 상한 값은 정수 1~100 범위만 받아요. 값이 비정상이면 **기본값(5/15/1)으로 되돌려 쓰고** 화면에 경고를 띄워요(상한이 사라지는 쪽으로는 절대 실패하지 않아요).

### 3-5. 변경 없는 공고의 AI 재검증 생략
공고마다 **검증키**를 저장해요: `해시( 정규화한 공고 본문 + 판정 규칙 버전 + 내 조건 버전 + 프롬프트/스키마 버전 )`.
- 다음 점검에서 본문을 다시 가져와 같은 방식으로 키를 계산해, **같으면 AI를 부르지 않고** 이전 결과를 재사용해요(`AI 검증 = 생략(변경없음)`, 기록에 `재사용` 표시).
- **정규화:** 공백·줄바꿈·조회수·게시 일시 같은 매번 달라지는 부분은 키 계산에서 빼요(그렇지 않으면 매번 달라 보여요). 정규화 규칙은 시험으로 고정해요.
- **다르면 재검증 대상:** 본문이 바뀐 경우(수정·마감 연장·재공고)는 B단계 대상이 되고 변경 이력이 남아요.
- **`내 조건`이나 판정 규칙이 바뀐 경우:** 전체 공고를 한꺼번에 AI에 다시 보내지 않아요. 추출된 필드(AI 결과)는 재사용하고, 적합도 판정이 코드로 가능한 부분은 코드가 다시 계산해요. 코드로 안 되는 공고만 `재검증 필요` 표지를 달고, 한도 안에서 작가님이 실행할 때 처리해요.
- **날짜 기반 상태**(마감 임박, 마감 확정)는 키와 무관하게 코드가 매일 다시 계산해요. AI 호출이 필요 없어요.
- 캐시는 `공고\cache\<검증키>.json`이고, 모드(`mock`/`real`)별로 분리해요(Mock 결과가 실제 결과로 재사용되는 것을 막아요).
- 한계: 검증 결과가 틀렸던 공고는 같은 본문이면 틀린 채로 재사용돼요. 작가님이 수동 판정을 고치면 그 수정이 우선하고, "다시 검증" 버튼(한도 적용)으로 캐시를 무시할 수 있어요.

## 4. 측정 방법 (먼저 측정, 나중에 최적화)

- 기존 `usage.js`가 이미 하는 일: 호출 1건마다 한 줄(직원·편·AI·모델·추론강도·결과·종료코드·소요초·웹검색 횟수·토큰·환산비용)을 `작업\사용량.jsonl`에 기록, Codex는 `turn.completed`의 usage, Claude는 최종 JSON의 usage를 읽어요 [확인]. → 그대로 재사용하고 **단계 이름·공고 수·실행 ID·캐시 적중 여부**를 추가해요.
- **측정/추정/조회 불가 표시 규칙**
  - Claude: 토큰 = 측정(CLI 출력), 비용 = `환산`(구독이면 실제 청구가 아님을 표시)
  - Codex: 토큰 = 측정(`--json` 이벤트), 비용 = 단가표 없으면 `계산 불가`
  - 구독형 한도(Codex/Claude): **잔여량 조회 불가**. 한도 오류가 나야 알 수 있어요(15편 기록에 "1:35 PM에 다시 시도" 문구가 남아 있어요). 화면에는 "조회 불가"라고 쓰고, 최근 한도 오류 시각만 보여줘요.
  - API 키 방식은 구독과 **별도 항목**으로 따로 합산해요(섞지 않아요).
- 무엇이 많이 쓰는지 알려면: 실행당 `입력 토큰`, `출력 토큰`, `호출 수`, `재검증 생략 건수`(검증키 적중 — 코드가 센 값이라 **측정**), 그리고 호출 전 **추정** 입력 글자 수와 실제 토큰을 나란히 표시.
- **기록 항목 구분:** 호출 수·생략 건수·소요 시간 = 측정 / 토큰 = CLI가 준 경우 측정, 못 받으면 `기록 없음` / 글자 수 기반 값 = 추정(`추정` 라벨) / 비용 = 환산 또는 계산 불가 / 한도 잔여 = 조회 불가. 사용량 줄에는 `모드`(mock/real)와 `단계`(B)를 함께 남겨요.

## 7. 예상 모델 호출량 (MVP 개발·시험 기간, **계획 상한이지 예측이 아니에요**)

호출 = 모델을 실제로 부른 횟수(재시도 포함). 토큰 수는 **측정 전이라 산정하지 않아요**(추측 금지). 첫 실측 뒤 이 표에 채워 넣어요.

| 단계 | 실제 AI 호출 | 근거 |
|---|---|---|
| 개발 1~4 (형식·저장·수집·비교·화면) | **0회** | Mock 모드 + AI 단계가 없는 코드 |
| 개발 5 (AI 추출 연결) | Mock으로 0회 → 실제 연결 확인 **1~2회** | 작가님이 실제 모드를 켠 뒤, 공고 1~3건짜리 한 배치 |
| 4단계 실험 (실제 공고 10건) | 정상 **2회**(배치 5건 × 2), 재시도 포함 최대 **4회** | 배치 크기 5 가정 |
| 예비 (실패 재확인 등) | 최대 **4회** | |
