# 공고 사무실 완성안 — 구현 전 확인본

작성일: 2026-10-24
상태: 2026-10-24 작가님 구조 변경 승인. 원문 미확보분 신규 지침 작성·플랫폼시티 메인 지정 후 분야별 화면·기관 목록·연결 코드 구현. 전체 출처 수집과 실제 AI 성공 검증은 미완료. 최신 범위는 루트 README와 `NOTICE_IMPLEMENTATION_STATUS.md`를 봐요. 아래는 승인 당시 계획을 보존한 내용이에요.

## 현재 확인한 상태

사무실 그림과 공고 관리 화면, 시험 자료 기반 수집·검증, 저장·중복·변경·누락 기록, 호출 상한 관리 코드가 있어요.

- `사무실/notice/routes.js`: 실제 모드의 수집 요청은 501 오류로 막혀 있어요.
- `사무실/notice/clients.js`: RealClient는 준비되지 않은 상태이고 실제 AI 추출 구현이 없어요.
- `공고/settings.json`, `공고/institutions.json`: 확인 당시 없었어요. 판정규칙 기본값도 비어 있어요.
- `사무실/실행.bat`: 실제 모드를 켜는 환경 설정이 없어요.
- `사무실/notice/store.js`, `differ.js`: 현재 지역·인천 제외·추천 규칙은 강사 분야 중심으로 공통 적용돼요.
- `사무실/notice/verifier.js`: 본문이 있으면 원문확인됨으로 시작하는 기존 흐름은 실제 수집 시 공식 페이지를 확보했다는 증거와 구분해야 해요.
- `README.md`는 여전히 블로그 중심이라 공고 사무실 사용법 보완이 필요해요.

현재 직원 카드는 블로그용 5장이고, 공고 담당의 실제 운영 지침 카드는 없어요.

## 확인할 구조

방은 기존 공고정보센터 하나를 유지하고, 그 안에 검색 종류 선택을 넣어요.

| 검색 종류 | 수집·검증 내용 | 결과 표시 |
|---|---|---|
| 강사·양성과정·콘텐츠 | 용인·성남·수원 우선, 경기·서울, 인천 제외. 강사·교육생·창작 지원·캐릭터 IP 검색 | 신규·놓침·변경·연장·취소·마감 임박 |
| 창업지원 | 기존 지침 원문을 추가 확보해 지역·키워드·예외를 확정 | 원문 미확보 항목은 연결 준비로 표시 |
| 임대주택 | LH·GH·마이홈·용인시·플랫폼시티·경기도·국토부·청약홈 및 사업 시행기관, 오전/오후 비교 | 사실·변경·누락 보고. 개인 자격 추정과 추천 없음 |

검색·검증·운영은 기존 직원 세 자리로 유지해요. 검색은 게시판과 키워드 탐색, 검증은 공식 원문·첨부 대조, 운영은 이전 실행 비교·마감·누락·보고를 맡아요. 직원 이름마다 별도 AI를 실행하지 않아요. 필요한 AI 추출만 현재 호출 기록과 예산 장치를 거쳐 실행해요.

파일은 모두 `{스튜디오}` 안에 두고, 분야별로 기관·설정·공고·실행·비교 기록을 분리해요. 기존 mock 데이터와 실제 자료도 분리해요. 기존 시험 자료에 분야가 없을 때는 강사로 읽는 호환 방안을 적용하고 기존 기록을 덮어쓰지 않아요.

## 원문과 현재 설계의 차이 — 적용 제안

1. **첨부 확인:** 공식 첨부의 읽기와 내용 추출을 추가해요. PDF/HWP/HWPX 등 추출 실패는 미확인으로 표시하고 완전 검증으로 계산하지 않아요. 이것은 현재 MVP의 첨부 자동 해석 제외 방침을 바꾸는 제안이에요.
2. **호출 상한:** 기존 상한을 유지하되 처리되지 않은 공고와 미점검 출처를 남기고 다음 실행에서 이어가요. 무제한 검증과 동일하다고 표시하지 않아요.
3. **품질 표시:** 기관 목록·원문·첨부·이전 비교의 성공/전체를 표시해요. 원문의 가중 확인율(60/25/10/5)을 추가할 경우 실제 근거 건수로만 계산하고, 지원 적합성의 확률과 구분해요.
4. **실행 시각:** 복구한 기록은 강사 오후 3시, 주택 오후 2시예요. 창업과 주택 아침의 전체 설정은 미확보예요. 기존 ChatGPT 자동화를 유지하고 새 사무실 정기 실행 시각은 별도 설정해 중복 실행을 방지해요.

## 구현 순서와 완료 기준

1. 분야별 자료 형식·설정·원문 연결·기관/키워드 목록·공고 직원 지침을 작성해요.
2. 실제 게시판 수집과 공식 본문 확보를 연결해요. 접근 실패·목록 해석 실패·첨부 실패·미실행을 나누고, 30일 조회 범위가 끝까지 확인됐는지 기록해요.
3. 기존 AI 실행기에 공고 검증을 연결해요. 검증기는 도구 없이 전달받은 자료만 읽고, 실제 호출 전에 예상량을 보여줘요. 개발 시험은 모의 응답으로 해요.
4. 날짜·시간·24:00 경계·수정/연장/취소·중복·누락·오전/오후 비교·7일/D-3/D-1/당일 재표시를 연결해요.
5. 기존 화면에 분야 선택·직원 진행·현재 출처·진행 건수·미처리·결과 보고·재개 기능을 붙여요. 주택 화면에는 지원 가능·추천 판정을 표시하지 않아요.
6. 별도 포트·별도 시험 자료로 검증하고, 실제 사이트 읽기와 실제 AI 1회 확인은 결과를 구분해 기록해요. 실행 중 서버를 임의로 종료하지 않아요.

완료는 3종 각각에서 실제 출처 → 후보 저장 → 공식 원문/첨부 상태 → 이전 기록 비교 → 화면 보고까지 확인했을 때로 정해요. 미확보 지침·미연결 사이트·미확인 첨부가 남으면 그 범위를 명시하고 전체 완료라고 하지 않아요.
