# AI 사무실 (AI Office)

**AI 직원들이 일하는 모습을 한 화면에서 보면서, 사람이 승인하고 결정하는 로컬 작업 사무실**이에요. 지금은 두 가지 일을 맡아요.

- **공고 정보센터** — 강사·양성과정·콘텐츠 / 창업지원 / 주택 공고를 공식 게시판에서 모아 비교하고, AI 는 꼭 필요한 해석에만 써요. (현재 중심 기능)
- **블로그팀** — 주제 기획 → 글쓰기 → 마감 검수를 직원별로 나눠 진행해요. (기획·글쓰기까지 연결, 이미지·마감은 설계 단계)

## 목적

AI 에게 일을 통째로 맡기면 무엇을 했는지 알기 어렵고, 사용량도 통제하기 어려워요. AI 사무실은 반대로 설계했어요.

1. **일반 코드가 일하고, AI 는 해석만 해요.** 가져오기·비교·중복 제거·날짜 계산은 코드가 하고, 모델 호출은 공고 본문을 구조화하는 한 단계에만 있어요.
2. **사람이 결정해요.** 새 글 주제 승인, 검증 실행 전 호출 수 확인처럼 결정 지점마다 멈춰서 승인받아요.
3. **실패를 숨기지 않아요.** 접속 실패·부분 확인·자동 수집 제한(robots.txt)은 성공으로 바꾸지 않고 그대로 표시해요. 한도에 걸리면 처리하지 못한 건을 보존하고 이어서 해요.
4. **외부로 나가는 길을 만들지 않아요.** 지원서 제출·메일 발송 코드는 없어요.

## 아키텍처

```text
 브라우저 (사무실/public)  ◄── 4초 간격 갱신 ──►  server.js  (Node 내장 모듈만, 127.0.0.1:4173)
   직원 캐릭터 · 방(블로그팀/공고)                    │  같은 출처(Origin) + x-office-request 헤더 요청만 허용
   공고 패널 · 승인 버튼                              │
                                                      ├─ 블로그팀: planner.js · writer.js ─► runner.js ─► `codex exec` (read-only / workspace-write)
                                                      │                  상태/NN.json · 작업/NN/ (주제확정서, 조사메모, 원고)
                                                      │
                                                      └─ 공고 센터: notice/routes.js
                                                           ├─ 수집(코드): collector · webfetcher · extractor · attachments(PDF/HWPX/DOCX)
                                                           ├─ 비교(코드): differ · deadline · housing · profiles · sources
                                                           ├─ 검증(AI):   verifier ─► realclient ─► Claude (도구 없이 JSON 추출)
                                                           └─ 저장(코드): store · budget · metrics · report  (파일 기반, 원자적 저장)
```

| 폴더 | 역할 |
|---|---|
| `사무실/` | 서버와 화면. `office.config.json` 이 방·직원·그림·상태별 소품을 정의 |
| `사무실/notice/` | 공고 센터 코드. 수집기와 검증기가 서로의 함수를 부르지 않고 **저장된 파일 상태로만** 이어짐 |
| `직원/` | 직원별 카드(역할·읽을 문서·쓸 수 있는 위치). 프로그램이 직원을 실행할 때 그대로 넘기는 지시문 |
| `규칙/` | 직원과 결재, 상태 파일 형식, 검색 지침(공통·창업·주택) 등 운영 규칙 |
| `공고/` | 실행 중 쌓이는 수집 자료 (Git 제외). `기존자동검색/` 만 지침 원문으로 포함 |
| `상태/`, `작업/` | 편별 진행 상태와 직원 간 인계 문서 (Git 제외) |
| `docs/` | 설계·감사·구현 현황 문서 |

## 작동 방식

### 공고 정보센터: 두 개의 독립 단계

```text
 기관 목록 ─► ① 수집 ─► ② 비교 ─► ③ 본문 확보 ─► ④ 분류 ─┐     (A. 수집: AI 호출 0회)
                                                          ▼
 ⑦ 저장·반영 ◄─ ⑥ 원문 대조 ◄─ ⑤ AI 추출·판정 (배치) ◄───┘     (B. 검증: 모델 호출은 ⑤ 만)
```

1. **게시판 점검(A)** — 등록한 공식 사이트의 목록을 읽어요. `robots.txt` 가 자동 수집을 막으면 우회하지 않고 "자동 확인 제한"으로 기록해요. 새 글이 없으면 여기서 끝나서 **AI 를 한 번도 부르지 않아요.**
2. **검증 실행(B)** — A 가 저장한 "검증 대상" 공고만 모아 Claude 에 보내요. 버튼에 예상 호출 수가 먼저 표시돼요. 응답의 근거 문장이 원문에 실제로 있는지 코드가 대조하고, 근거가 없으면 확정하지 않아요.
3. **직원 보고** — 신규·수정·연장·취소·놓침·마감 임박을 구분하고, 미확인 출처를 따로 모아 보여줘요. 공고는 지우지 않고, 제외·검증 생략·추천 제외·보존은 서로 독립된 값으로 기록해요.
4. **사용량 통제** — 실행당 5회·하루 15회가 기본 상한이에요. 한도에 닿으면 멈추고 남은 건을 "미처리"로 보존하며, 같은 본문·규칙이면 결과를 재사용해 다시 호출하지 않아요.
5. **모드** — `실행.bat` 은 실제 자료 모드, `시험모드.bat` 은 가짜 기관·가짜 응답(Mock)으로 AI 호출 없이 화면을 시험해요.

검색 종류 3종은 `사무실/notice/profiles.js` 에 키워드·필수 출처가 있고, 지침은 `규칙/05~07` 에 있어요.

### 블로그팀

1. **새 글 기획 시작** — 기획 직원(Codex, read-only)이 기존 주제·진행 현황·운영 지침을 읽고 후보 3~5개와 다음 편 번호를 제안해요.
2. **승인 / 반려** — 사람이 후보를 고르거나 이유를 적어 반려해요. 승인 전에는 아무 파일도 확정되지 않아요.
3. **글쓰기** — 승인된 주제확정서와 조사메모로 원고(MD/TXT)를 만들어요. 허용된 경로에만 쓰고, 승인 후 바뀐 입력은 감지해서 멈춰요.
4. 한도·로그인 오류는 완료로 처리하지 않고 실패 기록을 보존해요. 서버가 재시작되면 진행 중이던 기록을 "중단"으로 표시하고 재시도할 수 있어요.

## 시작하기

요구사항: Windows, Node.js 20 이상 (npm 패키지 설치 불필요). 실제 모드에는 로그인된 Claude CLI 와 Codex CLI 가 필요해요. **이 프로그램은 API 키를 저장하지 않고**, PC 에 로그인된 CLI 를 호출해요. PDF 첨부를 읽으려면 Python 과 `pypdf` 가 필요해요.

```bash
# 화면만 먼저 보기 (AI 호출 없음, 가짜 데이터)
사무실/시험모드.bat

# 실제 모드
사무실/실행.bat
```

브라우저에서 http://127.0.0.1:4173 이 열려요. 서버는 이 컴퓨터에서만 접속돼요.

### 내 환경에 맞추기

- `직원/*.md`, `규칙/*.md` 의 `{스튜디오}` 는 이 폴더의 절대 경로로, `{블로그}` 는 연결할 블로그 자료 폴더의 절대 경로로 바꿔서 쓰세요. 직원 카드는 절대 경로를 전제로 쓰여 있어요.
- 블로그 자료 폴더는 환경 변수 `OFFICE_BLOG_ROOT` 로 지정할 수 있어요. 지정하지 않으면 `~/OneDrive/Documents/꿀벌블로그` 를 찾아요.
- 포트는 `OFFICE_PORT` 로 바꿀 수 있어요.

## 테스트

```bash
node 사무실/tests/notice.unit.test.cjs       # 공고 단위 시험
node 사무실/tests/notice.server.test.cjs     # 공고 서버 통합 시험
node 사무실/tests/notice.profiles.test.cjs   # 검색 3종·날짜·robots 시험
node 사무실/tests/planner.test.cjs           # 기획 흐름
node 사무실/tests/writer.test.cjs            # 글쓰기 흐름
```

시험은 임시 폴더와 모의 실행기만 쓰고, 외부 프로세스·네트워크 호출을 막는 장치(tripwire)가 있어요.

## 현재 상태와 알려진 한계

- 공고 단위 시험 24개 중 1개(`S7` 하루 호출 상한 합산)가 실패해요. 호출 수 계산 기대값이 8 대 6 으로 어긋나는 문제로, 아직 원인을 고치지 못했어요.
- 실제 Claude 호출은 연결 코드만 구현했고 **실제 인증·응답 성공은 검증하지 않았어요.**
- 등록한 시작 출처는 일부(강사 4·창업 3·주택 6)이고, 동 주민센터·도서관 등 전체 출처 등록은 끝나지 않았어요. 동적 게시판은 추출 실패로 남아요.
- HWP·스캔 문서는 읽지 못해 "미확인"으로 표시해요. 정기 실행 예약은 없고 화면에서 수동으로 시작해요.
- 블로그팀은 기획·글쓰기까지만 연결돼 있고 이미지·마감 직원은 설계 표시만 있어요.

자세한 설계와 감사는 [`docs/`](docs/) 를 보세요. 개발자용 규칙은 [`AGENTS.md`](AGENTS.md) 에 있어요.
